# Step 1: Project Setup and PostgreSQL

## Overview

Step 1 establishes the initial BookShelf Django project. The project is now
configured to use PostgreSQL, loads local configuration from a `.env` file,
and contains the three Django applications required by the project:

- `books`
- `library`
- `recommender`

This step does not include database models, pages, search, authentication
flows, book importing, reviews, or recommendations. Those features belong to
later steps in [`instruction_Ai.md`](./instruction_Ai.md).

## Project goal and fixed technology choices

BookShelf will become a small Goodreads-style website where users can:

- Browse and search books.
- Add books to personal shelves.
- Rate and review books.
- Receive recommendations generated by an offline TF-IDF model.

The implementation follows these fixed choices from the project instructions:

- Python 3.10 or newer.
- Django 5.
- PostgreSQL with `psycopg2`.
- Django function-based views.
- Plain HTML, CSS, and JavaScript.
- Django templates instead of React.
- No CSS framework.
- No npm.
- No REST API at this stage.
- scikit-learn and pandas for machine learning.
- Open Library API for book data and cover images.
- All machine-learning code will eventually live in
  `recommender/services.py`.

## Environment configuration

The `.env` file contains the local development configuration:

```text
SECRET_KEY=change-me
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1
DB_NAME=bookshelf
DB_USER=vivesh
DB_PASSWORD=password
DB_HOST=localhost
DB_PORT=5432
```

Important notes:

- `.env` is ignored by `.gitignore` because it contains credentials and local
  configuration.
- `DB_USER` and `DB_PASSWORD` must match the PostgreSQL role on another
  machine.
- `SECRET_KEY=change-me` is only a development placeholder and must be
  replaced before production use.
- `DEBUG=True` is suitable only for local development.
- `ALLOWED_HOSTS` can be expanded when the project is deployed.

## Django settings configured

[`bookshelf/settings.py`](./bookshelf/settings.py) was updated to:

### Load environment variables

The project imports `os` and `load_dotenv`, then loads the root `.env` file:

```python
from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent
load_dotenv(BASE_DIR / '.env')
```

### Read core settings from `.env`

The following values are loaded from environment variables:

- `SECRET_KEY`
- `DEBUG`
- `ALLOWED_HOSTS`

`DEBUG` is converted from text to a Boolean value. `ALLOWED_HOSTS` is split
into individual host names and whitespace is removed.

### Register installed applications

The default Django applications remain enabled, and these applications were
added:

```python
'django.contrib.postgres',
'books',
'library',
'recommender',
```

`django.contrib.postgres` is enabled so later models can use PostgreSQL
features where appropriate.

### Configure the top-level templates directory

The template configuration now points to:

```python
'DIRS': [BASE_DIR / 'templates']
```

This allows shared templates to be stored in the project-level `templates/`
directory.

### Configure PostgreSQL

The default SQLite configuration was replaced with PostgreSQL:

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': os.environ['DB_NAME'],
        'USER': os.environ['DB_USER'],
        'PASSWORD': os.environ['DB_PASSWORD'],
        'HOST': os.environ.get('DB_HOST', 'localhost'),
        'PORT': os.environ.get('DB_PORT', '5432'),
    }
}
```

The database name, user, and password are required from `.env`. The host and
port default to `localhost` and `5432` if they are not explicitly provided.

### Configure static files

The project-level static directory is registered with:

```python
STATICFILES_DIRS = [BASE_DIR / 'static']
```

### Configure login and logout redirects

Both redirects currently point to the site root:

```python
LOGIN_REDIRECT_URL = '/'
LOGOUT_REDIRECT_URL = '/'
```
